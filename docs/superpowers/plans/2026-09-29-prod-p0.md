## Goal

Stop silent wrong numbers from shipping: pin the seasonal analysis to known answers from
real data, make the monitoring pipeline independent of terra's scale handling and loud
about skipped layers, check ETc against an independent formula in the live-API gate, and
let users silence progress messages with `options(Rwapor.verbose = FALSE)`.

  Its only caller is `R/wapor_monitoring.R:431` (`wapor_run_monitoring()`), which ignores the
  return value.
- `R/utils.R:1111` `log_msg()` always calls `message()`; progress `message()` calls are spread
  over several files (listed in Step 3).
- `inst/bench/live_release_checks.R` — manual live-API gate (run by CI job "live API").
  Its seasonal check (line 81) only compares API vs local AETI; ETc was never checked, which is
  how ISS-20260929-017 (ETc from a shifted Kc curve) passed.

```r
ka_flatten <- function(x, prefix = "") {
  if (inherits(x, "SpatRaster")) return(stats::setNames(list(x), prefix))
  out <- list()
  if (is.list(x) && !is.data.frame(x)) for (n in names(x)) if (nzchar(n)) {
    out <- c(out, ka_flatten(x[[n]], if (nzchar(prefix)) paste0(prefix, "$", n) else n))
  }
  out
}
```

### 2. Monitoring hardening (`R/wapor_monitoring.R`, `wapor_save_raster_blobs()`)

a. **Scale once**: immediately after `r_stack` is final (after the batched open, or after the
   per-layer fallback builds it; before the CRS/extent logic), call
   `src <- .wapor_detach_source_scale(r_stack); r_stack <- src$raster`. After `r_stack_crop`
   is created successfully:
   `r_stack_crop <- .wapor_apply_source_scale(r_stack_crop, src$scale, src$offset)`
   (`src` is computed on `r_stack` itself, so the vectors align with its layers).
b. **Separate counters**: `n_existing <- length(urls) - length(pending_idx)` (already saved),
   `failed <- character(0)` (date keys). Every place that currently does `n_skip <- n_skip + 1L`
   appends `date_key` to `failed` instead. The per-layer fallback appends the date keys of
   layers whose open failed. A failed DB save (the `error = function(e) log_fn(...)` around
   `.package_save_global_raster_blob_to_db`) also appends `date_key`.
c. **No invented dates**: in the `date_keys` `vapply`, the error fallback returns
   `NA_character_` when no `YYYY-MM-DD` is found in the file name (never `Sys.Date()`).
   URLs with `NA` date keys are removed from `pending_idx` and reported in `failed` as
   `paste0("undated:", basename(url))`.
d. **Return value**: the function returns
   `invisible(list(variable = variable, saved = n_ok, existing = n_existing, failed = failed))`
   on every path. Early returns: no duckdb -> `saved = 0L, existing = 0L, failed = character(0)`;
   no URLs -> same; all already saved -> `existing = length(urls)`; batch not overlapping,
   crop failed, or no layer opened -> all pending date keys in `failed`.
   The outer `tryCatch` error handler keeps logging and returns
   `invisible(list(variable = variable, saved = 0L, existing = NA_integer_, failed = paste0("error: ", conditionMessage(e))))`.
e. **Loud failures**: the final log line becomes
   `"  Saved %d new layer(s) for %s; %d already saved; %d failed."`. When `length(failed) > 0`,
   also `warning(sprintf("%d layer(s) of %s were not saved: %s", length(failed), variable,
   paste(utils::head(failed, 5), collapse = ", ")), call. = FALSE)` (append ", ..." when more
   than 5). The warning is raised outside the outer `tryCatch` so it is not swallowed.
   Do not change `wapor_run_monitoring()`.
f. Roxygen `@return` of `wapor_save_raster_blobs()`: document the list.

```
## Reliability

* Known-answer tests pin every output of `wapor_run_seasonal_analysis()` (236 values,
```

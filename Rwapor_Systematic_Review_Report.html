1. Executive Summary & Review Scope

The Rwapor R package provides high-performance access to the Food and Agriculture Organization (FAO) WaPOR (Water Productivity Open-access portal) version 3 and Copernicus AgERA5 climate datasets. It incorporates an automated Cloud-Optimized GeoTIFF (COG) streaming pipeline, a seasonal crop water productivity analysis engine, zonal statistics and performance classification engines, farm-scale DuckDB persistence, and an interactive Shiny dashboard.

This systematic review was conducted from the perspective of a Senior Developer specializing in Big Data Geospatial Processing and COG Raster Streaming in R. The objective is to evaluate architectural integrity, computational scaling, numerical precision, memory efficiency, and scientific rigor prior to declaring the package production-ready.

Key Finding: Rwapor has evolved from an experimental download wrapper into a sophisticated analytical package. Its core raster processing has been modernized to use terra, sf, and exactextractr exclusively, deprecating legacy raster/sp dependencies. Its remote I/O pipeline achieves near-local read speeds via tailored GDAL HTTP streaming settings. However, critical gaps exist in DuckDB storage mechanisms, documentation citations for fundamental agronomic equations, and package build configurations under restricted disk environments.

2. Senior Developer Geospatial & Big Data Assessment

Handling multi-gigabyte spatio-temporal remote sensing cubes requires strict adherence to out-of-core computing, bounded memory allocation, and minimal network serialization. Here is the evaluation of Rwapor's big data design patterns:

2.1 Modern Geospatial Toolchain

  • terra & sf Adoption: The package strictly enforces terra for SpatRaster operations and sf for vector geometries. The legacy, slow, and memory-inefficient raster, sp, and rgdal packages are completely bypassed.
  • Pixel-Weighted Zonal Extraction: Zonal statistics across irregular polygons use exactextractr::exact_extract() and a custom C++/R engine in R/zonal_stats.R. This avoids coarse rasterization artifacts by calculating exact fractional pixel polygon overlaps.
  • Ellipsoidal Authalic Latitude Area Calculation: In R/zonal_stats.R (lines 121–137), cell areas for geographic (lon/lat) rasters are computed using the authalic latitude equations on the WGS84 ellipsoid (Snyder 1987, Eq. 3-12). This resolves the ~0.3% spherical error inherent in standard exactextractr spherical formulas at mid-latitudes (e.g., 32°N in the Near East and North Africa).

2.2 Cloud-Optimized GeoTIFF (COG) Streaming & GDAL Configuration

WaPOR v3 raster assets are hosted as tiled, multiresolution Cloud-Optimized GeoTIFFs (COGs). Accessing them over HTTP via GDAL's virtual file system (/vsicurl/) requires deliberate tuning:

  • Elimination of the 10 MB Chunk Size Trap (ISS-20261005-001): Prior versions set CPL_VSIL_CURL_CHUNK_SIZE = 10485760 (10 MB). Because GDAL downloads entire chunks on first touch, querying a small polygon (e.g., 50x50 pixels) forced downloading 10 MB to 20 MB per date. Removing this forced chunk default in R/gdal_config.R allows GDAL to revert to its dynamic 16 KB default, reducing Level 2 extraction time from 343 s (1,091 MB transferred) down to 21 s (17.4 MB transferred) for identical output.
  • Directory Listing Suppression: Setting GDAL_DISABLE_READDIR_ON_OPEN = "EMPTY_DIR" prevents GDAL from issuing wasteful HTTP requests attempting to enumerate remote directories on cloud object storage.
  • Scoped Extension Filter: The package applies CPL_VSIL_CURL_ALLOWED_EXTENSIONS = ".tif,.tiff,.TIF,.TIFF" only within scoped remote I/O blocks (.wapor_with_remote_io()), stopping GDAL from probing for non-existent sidecar files (.ovr, .aux.xml).
  • Scale/Offset Separation: Terra handles embedded raster scale factors differently across versions (pending vs. applied). R/wapor_map.R implements .wapor_detach_source_scale() and .wapor_apply_source_scale() to guarantee that Int16 COGs with scale 0.1 are multiplied exactly once, preventing double-scaling errors (e.g., values 10x too low).

2.3 Out-of-Core Processing & Bounded Memory Quantiles

In R/analysis_indicators.R (lines 305–430), the function .wapor_zonal_quantile_exact() implements an exact multi-pass streaming quantile algorithm (matching stats::quantile(type = 7)). Rather than reading millions of pixels into an R vector to compute the 95th percentile ($P_{95}$), it reads blocks via terra::blocks(), uses a 4,096-bin dynamic histogram to narrow down candidate bins, and only gathers values falling within the target bin. This ensures constant memory overhead regardless of whether the study area covers 1,000 or 50,000,000 pixels.

3. Module 1: Core API & Metadata Discovery

Primary Source Files: R/api_client.R, R/metadata.R, R/wapor_res_key.R, R/wapor_metadata_cache.R

Architectural Findings

  • API Resilience: The client uses httr2 with exponential backoff (up to 5 retries, capped at 30 s), honors Retry-After response headers, and classifies HTTP 429 and 5xx errors as transient.
  • Two-Tier Caching: API responses are cached both in-memory via memoise and on-disk under tools::R_user_dir("Rwapor", "cache")/url_cache using SHA-256 URL hashes. A default 24-hour TTL prevents stale metadata while allowing offline repeated querying.
  • Level Fallbacks: The helper .wapor_resolve_level_fallback() consolidates the architectural rule where Reference Evapotranspiration (RET) and Precipitation (PCP) query Level 1 when requested under Level 2 or Level 3 (since FAO does not generate 100m/20m RET or PCP).
  • Time Slice Planner: wapor_plan_time_slices() dynamically decomposes arbitrary calendar intervals into the optimal minimum number of raster queries (Annual → Monthly → Dekadal → Daily), avoiding redundant single-day fetches.
Identified Issue (API-01): wapor_variable_metadata() relies heavily on hardcoded R objects (WAPOR3_VARS and AGERA5_VARS). While JSON mirrors exist in inst/metadata/, there is no automated schema validation against live FAO GISMGR API endpoints. If FAO updates metadata attributes or adds products, package updates require manual code edits.

4. Module 2: Ingestion, COG Streaming & Download

Primary Source Files: R/wapor_map.R, R/wapor_ts.R, R/download_cache.R, R/gdal_config.R, R/wapor_cog.R

Architectural Findings

  • Dual-Mode Downloading:
    • wapor_map(): Streaming windowed extractor that creates cropped SpatRaster stacks or seasonal aggregates directly from remote URLs.
    • wapor_download(): Offline-first cache downloader that stores physical Float32 GeoTIFFs structured as <folder>/<variable>/<provider>.<variable>.<date>.tif. It is idempotent, skips existing files, and performs atomic writes via temporary files (.partial.tif).
  • Multi-Temporal Weighted Aggregation: Handles dekadal length variations automatically (10 days for dekads 1 and 2; 8–11 days for dekad 3 depending on month and leap year). Intensive variables (temperature, soil moisture) use weighted means, while flux variables (evapotranspiration, rainfall) use weighted accumulation.
  • Atomic COG Writer: wapor_write_cog() in R/wapor_cog.R automatically determines whether the GDAL COG driver is present, selects floating-point (PREDICTOR=3) vs. integer (PREDICTOR=2) predictors, probes appropriate datatypes (INT1U through FLT8S), and triggers BIGTIFF when uncompressed volume exceeds 3.5 GB.
Identified Issue (DL-01): While wapor_download() records AOI metadata in .wapor_download.json to prevent overlapping extents from colliding in the same directory, wapor_map() does not enforce this guard when writing separate files into a user-specified folder.

5. Module 3: Seasonal & Spatial Analysis Engine

Primary Source Files: R/analysis.R, R/analysis_engine.R, R/analysis_indicators.R, R/analysis_registry.R, R/zonal_stats.R, R/classify.R, R/performance_indicators.R

Architectural Findings

  • Pluggable Indicator Step Registry: R/analysis_registry.R implements a topological dependency resolver (wapor_ordered_indicator_steps()) that allows custom or third-party indicators to be registered and executed seamlessly within the core analysis pipeline.
  • Generalized Zonal Engine: wapor_zonal_stats() accepts arbitrary spatial units (sf polygons, SpatVector, or regular grid block sizes in meters), computes 18 different statistics (mean, median, quantiles, CV, CU, DU_lq, Gini, Theil, volumes, class shares), and supports nested polygon dissolving without duplicating calculations.
  • Monthly Split for Green & Blue Water (ISS-20260923-005): Correctly resolves the mathematical error of splitting green/blue water on seasonal totals. Since the USDA-SCS effective precipitation formula is monthly, green water ($\sum \min(AETI_m, P_{eff,m})$) and blue water ($\sum \max(0, AETI_m - P_{eff,m})$) are computed per month and accumulated.
  • Smart-Linking Masks: Allows multi-season runs to automatically pick up season-specific crop masks and phenology dates (seasonal_masks/<Season>_mask.tif).
Critical Discrepancy (ENG-01): In R/analysis_validation.R line 21, wapor_validate_analysis_config() enforces: 
if (!is.null(config$ref_year) && (config$ref_year < 2000 || config$ref_year > 2030)) {
  errors <- c(errors, "Reference year must be between 2000 and 2030")
}
However, the analysis engine default in R/analysis.R:1078, as well as published vignettes (advanced-analysis.Rmd:82 and wheat-water-productivity.Rmd:96), explicitly document and pass ref_year = 1970! Calling the validator on standard documented configs causes false validation failures.
Identified Issue (ENG-02): In R/analysis.R (lines 642–651), when constructing the daily $K_c$ curve for crops where the total season days are shorter than the sum of initial, mid, and late stages, l_dev becomes negative. The code emits a warning and returns an empty numeric vector (numeric(0)), causing downstream raster multiplication to fail completely rather than scaling stage lengths proportionally.

6. Module 4: Farm Monitoring & DuckDB Storage

Primary Source Files: R/wapor_monitoring.R

Architectural Findings

  • Schema Evolution: Database migrations are managed through .wapor_monitoring_migrate(), currently at schema version 2. Table definitions include farm polygons, timeseries statistics, grid registries, and monitoring rasters.
  • Spatial Grid Homogeneity Guard: .wapor_validate_raster_grid() registers the canonical bounding box, resolution, and CRS for each variable, preventing corrupt timeseries caused by inserting mixed-resolution raster grids.
Critical Flaw (MON-01 - ISS-20260923-002): Whole rasters are serialized as binary large objects (BLOB) into the DuckDB table monitoring_rasters.raster_blob. In wapor_generate_seasonal_raster() (lines 1012–1016): 
r_list <- lapply(seq_len(nrow(df)), function(i) {
  r_global <- wapor_raster_from_blob(df$raster_blob[[i]])
  terra::crop(r_global, f_ext)
})
Every query deserializes the entire raster tile into memory before cropping to the farm polygon! As the monitoring area grows, RAM consumption explodes, and windowed range reads are impossible. COG file paths or URLs must be stored instead.
Critical Mathematical Bug (MON-02): In wapor_generate_seasonal_raster() lines 1024–1030: 
is_flux <- grepl("AETI|PCP|NPP|^-T-|^E-", variable, ignore.case = TRUE)
if (is_flux) {
  res <- terra::app(s, fun = "sum", na.rm = TRUE)
}
Dekadal AETI is stored in mm/day. Simply calling sum across dekadal layers sums daily rates without multiplying by the number of days in each dekad ($N \in [8, 11]$)! This produces seasonal totals that are roughly 10x too small, conflicting with the verified logic in R/wapor_map.R.

10. Identified Gaps, Bugs & Architectural Risks

The systematic code review identified 8 technical issues categorized by severity:

Critical Severity (Blockers for Production Release)

  1. MON-01 (DuckDB Large Blob Storage - ISS-20260923-002): Storing full raster serializations inside DuckDB BLOBs creates severe memory leaks and prevents spatial indexing. Querying a 10-hectare farm requires deserializing full country/continental raster GeoTIFFs.
  2. MON-02 (Missing Dekadal Multipliers in Monitoring Aggregation): wapor_generate_seasonal_raster() sums dekadal rates (mm/day) directly instead of multiplying each layer by its number of days ($N \in [8, 11]$), yielding seasonal sums that are approximately 10x too low.
  3. ENG-01 (Validation Range Conflict on ref_year): wapor_validate_analysis_config() enforces ref_year ≥ 2000, but standard package defaults and vignettes pass ref_year = 1970, causing false errors on valid analyses.
  4. PKG-01 (.Rbuildignore Missing Archives): Root directory contains large archive files (training.zip 268 MB and Rwapor_1.0.0.tar.gz) that are copied into temporary build directories during R CMD build, causing immediate disk-full failures.

High Severity (Scientific Rigor & Citations)

  1. CIT-01 (Outdated inst/CITATION): Mentions version 0.1.0, links to a legacy Python repository, and cites outdated WaPOR v1 documents instead of modern WaPOR v3 peer-reviewed literature.
  2. CIT-02 (Unreferenced Agronomic Formulas in R/analysis_indicators.R): Fundamental functions (wapor_calc_cwp, wapor_calc_bwp, wapor_convert_npp_tbp, wapor_calc_yield_npp, wapor_calc_green_water, wapor_calc_blue_water) lack literature references and derivation explanations in their roxygen docstrings.
  3. ENG-02 (Kc Curve Failure on Short Crop Seasons): In R/analysis.R, when season length is shorter than $L_{ini} + L_{mid} + L_{late}$, l_dev becomes negative and returns numeric(0), aborting analysis instead of proportional stage compression.
  4. API-02 (Rigid Temperature Conversion Filter): is_temperature_variable() checks only TMIN and TMAX. If mean temperature (TAVG) or dewpoint temperature (TDEW) are requested, Kelvin-to-Celsius conversion is silently omitted.
